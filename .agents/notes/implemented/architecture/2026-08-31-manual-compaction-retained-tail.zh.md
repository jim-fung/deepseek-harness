# Agent Note: 手动压缩采用策略保留尾部，摘要指令感知逐字尾部

Status: implemented

[English](2026-08-31-manual-compaction-retained-tail.md) | 中文

## 问题

`compactNow` 以 `retainTokens = 0` 选取压缩区间，因此手动 `/compact` 会把直到最后一个表面节点之外的所有内容——包括最新的用户轮次——有损摘要。两份 README 却都承诺相反的行为（"the recent tail stays verbatim"、"the recent history is untouched"），而记录在案的零保留理由是为上下文溢出路径写的，在那条路径上强制最大缩减才是目的。加剧这一矛盾的是，`COMPACTION_INSTRUCTION` 从未告诉摘要器检查点之后会有逐字的近期尾部存续，因此摘要可能重复或抵触模型紧随其后读到的内容——而这正是手动压缩检查点最新鲜的时刻。

## 决策

`compactNow` 现在解析压力触发器所用的同一保留尾部：路由目标的策略（`resolveTargetPolicy`）按其适配器上下文窗口缩放（`resolveCompactSpec(...).retainTokens`）。一个保留旋钮同时治理两种触发器，文档契约对两者都成立。没有路由请求的会话保持 `0`——没有可据以定价保留的策略，摘要器自己的回退链决定摘要是否可能。容量守卫移入两个路径共享的 `requireContextWindow`，因此未声明容量的路由从任一触发器都以同一个目标特定错误响亮失败。

摘要指令新增一条规则：最近的对话在检查点之后逐字继续，不属于被压缩的区间，不得复述，细节应偏向区间末尾，使检查点干净地交接给逐字尾部。该常量在多次压缩间保持字节稳定，保留辅助调用的前缀缓存复用。

## 备选方案

**为手动路径设一个更小的独立保留预算。** 否决：同一事实的第二个旋钮会招致漂移；小于任一预算的会话本就没有可压缩的内容——命令会诚实报告这一点。

**保留最后一个已关闭轮次边界而非策略预算。** 否决：轮次边界保留是第二种保留概念，需要新的表面机制，而策略预算已经存在、按模型配置，并且正是自动路径使用者所体验的。

**保留零保留并修正 README。** 否决：README 陈述的是预期产品行为；零保留会在用户最依赖的时刻丢弃最新鲜的指令。

## 后果

手动 `/compact` 现在只压缩早于已解析保留预算的历史；对话完全落在该预算内的会话返回 `null`，命令报告没有可压缩内容。测试 harness 配置显式的小 `retainTokens` 使种子历史保持可压缩，一个新的真实 loop 测试固定该契约：旧交换折叠进检查点，新交换逐字存续。溢出路径的零保留不变，仍是文档记录的例外。指令变更同步更新两种语言 README 中引用的提示文本；没有 keyless 快照固定它。手动压缩现在在开启括号之前解析模型容量，因此原先假设 `compaction/start` 之前单微任务结算的测试改为用定时器结算。
